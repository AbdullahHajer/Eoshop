# Eoshop launch-product blueprint

الخطة العربية التفصيلية: [LAUNCH_SCOPE_AR.md](./LAUNCH_SCOPE_AR.md)

This folder is a planning artifact, not a change to the live application. The HTML prototype turns the product-launch discussion into four original visual models:

1. Merchant daily dashboard.
2. Merchant application tracking and requested corrections.
3. Platform store-application review workspace.
4. Platform operations view for an active store.

## Launch boundary represented by the prototype

### Required for the first release

- Daily merchant tasks, recent orders, product and stock attention.
- Store products, inventory, orders, design/content, checkout/delivery and store settings.
- A recoverable store application with policy-driven documents.
- A detailed platform review workspace with request-correction, reject and approve decisions.
- A clear merchant application timeline and a targeted resubmission path.
- An active-store operations page covering owner, domain, subscription, provisioning, publication and health.
- Server-owned permissions, audit records and privacy boundaries.

### Next release, not a launch blocker

- Customer directory and basic reports.
- Merchant staff invitations and bounded roles.
- Manual order creation for phone and WhatsApp sales.
- Configurable customer status notifications.
- Basic coupons and campaign links.

### Later phases

- Advanced analytics and forecasting.
- Marketing automation and abandoned-cart recovery.
- Marketplace, POS and carrier integrations.
- Loyalty, affiliate and advanced discount engines.
- Multi-warehouse inventory and product variants.

## Product rule

The platform reviews store applications and monitors store health. The merchant owns day-to-day customer order processing. Platform access to a customer's order must be exceptional, permission-scoped, justified and audited.
