## الهدف

مراجعة رحلة المتجر العام بعد اكتمال قالب Elegant وإغلاق عيوب الإطلاق التي تؤثر في تنقل العميل أو صدق وسيلة الدفع المرسلة إلى الخادم، دون توسيع النطاق إلى تصميم Tech Bento الجاري في فرع مستقل.

## داخل النطاق

- توحيد انتقالات صفحات المتجر العام وإرجاع حاوية العرض إلى بداية الصفحة عند كل انتقال فعلي.
- ضمان تطابق وسيلة الدفع المعروضة والمحددة مع الرسوم والتحقق والطلب المرسل والإيصال.
- اختبارات انحدار للتنقل من التذييل ولتبدل وسائل الدفع بعد تغيير إعدادات التاجر.
- تثبيت اختبار هوية نافذة المصادقة على التحديث غير المتزامن الفعلي لمتغيرات CSS.

## خارج النطاق

- لا تغيير API أو Backend أو Database أو Migration أو dependency.
- لا تعديل على مكونات `tech-bento` التي يعمل عليها المطور الآخر.
- لا إعادة تصميم بصري ولا تقسيم شامل لحزمة JavaScript.
- لا Merge قبل مراجعة PR مستقلة ونجاح CI.

## العيوب المغلقة

1. **موضع تمرير قديم بعد التنقل:** كان الانتقال من التذييل أو الهيدر أو نتائج التسويق يغيّر المحتوى مع الاحتفاظ بموضع التمرير السابق، فيظهر العميل بمنتصف الصفحة الجديدة. أصبح كل مسار تنقل داخلي يمر عبر وظيفة واحدة تعيد حاوية المتجر إلى البداية وتحترم تفضيل تقليل الحركة.
2. **اختلاف وسيلة الدفع الظاهرة عن المرسلة:** عند تبدل إعدادات التاجر أثناء جلسة العميل، كان الاختيار الفعلي المعروض قد يصبح الدفع عند الاستلام بينما تبقى حالة محفظة قديمة مستخدمة في الرسوم أو التحقق أو الطلب. أصبح المصدر التشغيلي الوحيد هو وسيلة الدفع المتاحة فعليًا في الإعدادات الحالية.
3. **اختبار مصادقة حساس للتوقيت:** أصبح التحقق من متغيرات الهوية ينتظر تطبيق أثر React بدل قراءة جذر المستند قبل اكتمال التحديث.

## معايير القبول والنتائج

- الانتقال بين الرئيسية والمنتجات وعن المتجر والتواصل والتفاصيل والدفع يبدأ من أعلى الصفحة.
- الحركة تكون فورية عند تفعيل `prefers-reduced-motion` وسلسة في الحالة العادية.
- لا يمكن إرسال محفظة أو تحويل بعد تعطيلها؛ الطلب والرسوم والإيصال تتبع الوسيلة المتاحة التي يراها العميل.
- قالب Tech لا يتلقى تركيبًا بصريًا جديدًا من هذه الحزمة.
- TypeScript وVite production build وVitest و`git diff --check` ناجحة.
