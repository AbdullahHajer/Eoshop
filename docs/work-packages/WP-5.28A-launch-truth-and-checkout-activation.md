# WP 5.28A — Launch truth and checkout activation

| الحقل | القيمة |
|---|---|

## النطاق

1. يحمل الإيصال الحي حالة الطلب التي أعادها الخادم ويعرض تسمية عميل صادقة؛ لا يدعي بدء التجهيز أو التوصيل عند `submitted`.
2. لا تعرض منصة الإدارة انتقالًا مباشرًا `rejected → pending` يرفضه `TenantPolicy`. قرار الطلب المرفوض لا يعاد فتحه من منصة الإدارة؛ العودة للمراجعة تمر فقط عبر تصحيح التاجر وإعادة الإرسال، فينشئ الخادم طلب نشر جديدًا ويعيد حالة التحقق إلى `pending`.
3. يبقى `ORDER_CHECKOUT_ENABLED=false` افتراضيًا، ويصبح مصدره في root Compose موثقًا ومختبرًا لحالتي on/off مع runbook تفعيل وتراجع.

## الحدود

- لا API أو Migration أو dependency أو تغيير لعقد الطلب.
- لا إضافة حالات توصيل؛ تنفذ في WP 5.28B بعد ADR مستقل.
- لا تغيير لسياسة الخادم الخاصة بالمتجر المرفوض.
- لا تمكين checkout افتراضيًا في ملفات المثال أو كود Laravel.
- لا أسرار أو قيم بيئة إنتاجية في Git أو مخرجات الاختبار.

## معايير القبول

1. إيصال طلب `submitted` يعرض «تم استلام الطلب» ولا يعرض «قيد التجهيز والتوصيل».
2. معاينة checkout تبقى «معاينة غير مرسلة».
3. متجر `rejected` لا يعرض زر «إعادة للمراجعة» ولا يستدعي status mutation مباشرًا؛ يبقى مسار التصحيح وإعادة الإرسال الخاص بالتاجر متاحًا وفق العقد الخادمي القائم.
4. اختبارات 403 وتسلسل mutations تستخدم انتقال `suspended → approved` الصحيح.
5. `.env.example` الجذري يوثق safe default `false`.
6. Repository gate يثبت انتقال `false` المصرح به في `.env.example` و`true` الصريح من بيئة العملية إلى `backend` و`worker` و`scheduler` دون طباعة البيئة. يبقى fallback الداخلي `${ORDER_CHECKOUT_ENABLED:-false}` ظاهرًا في Compose، لكنه ليس ما تسميه هذه الحزمة حالة unset مختبرة.
7. يشرح runbook التفعيل، canary، التحقق والتراجع، ويؤكد أن browsing يبقى متاحًا عند إيقاف checkout.
8. تنجح الاختبارات المركزة والبوابات الأربع و`git diff --check` على الرأس نفسه.

## المخاطر والضوابط

- قد يعيد تراجع واجهة الإدارة زر انتقال لا يسمح به الخادم؛ لذلك لا يعد تراجع الحزمة كاملًا تغيير نصوص فقط.
- قد يفعّل المشغل checkout في عملية ويب دون العامل أو المجدول؛ يمنع اختبار Compose هذا الانحراف بين الخدمات الثلاث.
- لا يثبت اختبار العلم المعطل عدد حجوزات المخزون مباشرة؛ يثبت استجابة `503` وعدم إنشاء طلب، بينما يبقى فحص عدم وجود حجز خطوة تشغيلية إضافية عند توفر وصول قاعدة البيانات.
- لا تعني تسمية حالة الإيصال إضافة دورة توصيل جديدة؛ حالة التنفيذ والتوصيل مؤجلة إلى WP 5.28B وعقد مستقل.

## التراجع

يمكن تعطيل إنشاء الطلبات تشغيليًا بإعادة `ORDER_CHECKOUT_ENABLED=false` وإعادة إنشاء الخدمات، دون تراجع الكود أو تغيير الطلبات القائمة. أما تراجع الحزمة كاملة فيعيد أيضًا عبارة الإيصال القديمة وزر الانتقال الإداري غير الصالح، لذلك لا يوصف بأنه تراجع نصي آمن؛ إن لزم تراجع جزئي فيجب إبقاء إصلاحي الصدق والإجراء الإداري، والتراجع عن توثيق/اختبار التشغيل فقط. تراجع وثيقة التشغيل أو اختبار Compose وحدهما لا يغير runtime، ويبقى kill switch نفسه وقيمته الآمنة `false` متاحين.
