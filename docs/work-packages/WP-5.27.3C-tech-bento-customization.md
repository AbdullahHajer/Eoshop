## النطاق

تغلق هذه الحزمة الفجوة بين واجهة Tech Bento المنشورة وبين لوحة تخصيص التاجر. يستطيع التاجر، من تبويب **القصص والمختارات** عند اختيار القالب التقني، إدارة:

- خمسة مربعات `hero_bento` كحد أقصى.
- إعلانين `side_ad` كحد أقصى، مع الإفصاح واسم الراعي.
- عشرة عناصر `discovery` كحد أقصى، وهي صور اكتشاف بلا سعر أو زر سلة.
- العنوان والوصف والشارة ونص الزر والصورة الأساسية وصورة الجوال والهدف.
- ألوان كل مساحة وتعتيم الصورة وموضعها والجدولة.
- التفعيل والترتيب والنسخ والحذف ضمن حدود العقد الخادمي.

يختار `MerchantStoreProfileEditor` المحرر الملائم لـ`themeStyle`: محرر Tech الجديد للقالب التقني، ومحرر Elegant القائم للقالب الأنيق. بيانات القالب غير المختار تبقى محفوظة ولا يعاد تفسيرها أو حذفها.

## ما أعيد استخدامه

- عقد `StorefrontMarketingBlock` المملوك للخادم.
- `marketingBlocks` داخل `StoreConfig` والحفظ revisioned القائم.
- رفع Store Assets القائم وعزل الأصل بحسب المتجر.
- إسقاط الواجهة العامة والتحقق من الأهداف والجدولة والروابط الخارجية على الخادم.
- Renderer Tech Bento الحالي؛ لم يُبن renderer ثانٍ أو مخزن متصفح موازٍ.

## الحدود المستمرة

- لا Migration ولا endpoint ولا جدول ولا dependency جديدة.
- لا تعديل في عقد API أو حدود الخادم.
- لا تعديل في مكونات `elegant-stories` أو محررها.
- المساحة الجديدة تبدأ معطلة حتى يكمل التاجر بياناتها ويختار تفعيلها.
- رفع الصور يقبل JPEG وPNG وWebP ويلتزم بميزانية كل placement وصورة الجوال.
- الرابط الخارجي يبقى حملة HTTPS مع إفصاح؛ الخادم هو صاحب القرار النهائي عند الحفظ.
